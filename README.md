# Delivery — 미니 배달 주문 서비스

사장님(`OWNER`)이 메뉴를 관리하고 손님(`CUSTOMER`)이 주문하는 Spring Boot 백엔드 학습 프로젝트다. 주문 한 건은 메뉴 한 개와 수량으로 구성하며, PostgreSQL은 Docker에서 실행한다.

기준일: **2026-10-08**. 결제 제외 오류 수정과 Postman 부분 재검증을 반영했다.

## 기술 및 실행 환경

| 구분 | 사용 기술 / 확인한 환경 |
|---|---|
| 언어·프레임워크 | Java 21, Spring Boot 4.1.1 |
| 웹·검증 | Spring MVC, Jakarta Validation |
| 인증 | Spring Security, JWT, BCrypt |
| 데이터 | Spring Data JPA, PostgreSQL 18.6 |
| 로컬 구성 | 개발자 PC의 Spring Boot → Docker `delivery-db`, 호스트 5432 → 컨테이너 5432 |
| 빌드·API 테스트 | Gradle Wrapper, Postman CLI 1.70.0 |

## 설계 및 구현

현재 소스에 구현된 구조와 기능은 다음과 같다. 자세한 관계·제약·요청 및 응답은 [설계 문서](./docs/README.md)에서 확인한다.

- **계층 구조:** Controller → Service → Repository. 요청·응답 DTO를 엔티티와 분리한다.
- **도메인:** `User`, `Menu`, `Order` 세 엔티티와 N:1 연관관계를 사용한다. 회원 역할로 사장님과 손님을 구분한다.
- **인증·권한:** 회원가입과 JWT 로그인, 서비스에서의 역할·소유권 검사로 메뉴와 주문 접근을 제어한다.
- **메뉴:** 등록·목록·단건 조회·수정·Soft Delete를 제공한다. 공개 GET 조회와 삭제 메뉴 제외를 적용한다.
- **주문:** 서버가 금액과 초기 `ORDERED` 상태를 결정한다. 생성·역할별 목록·취소·상태 변경 API가 구현되어 있다.
- **결제:** 엔티티와 API는 미구현이다. 문서의 결제 관계·테이블·API는 향후 구현을 위한 설계안이다.

주문 취소·상태 변경은 코드가 존재하지만 이번 PostgreSQL/Postman 재검증 대상에는 포함하지 않았다. 결제가 미구현이므로 정상 API 흐름으로 `ORDERED → PAID → ACCEPTED → COMPLETED` 전체를 검증한 상태는 아니다.

## 로컬 실행

1. Java 21을 준비한다.
2. Docker PostgreSQL을 실행하고 `localhost:5432`의 `delivery` DB에 접속할 수 있도록 설정한다.
3. [application.yml](./src/main/resources/application.yml)의 DB 접속 설정과 JWT 비밀키를 실행 환경에 맞춘다.
4. 프로젝트 루트에서 다음 명령을 실행한다.

```powershell
.\gradlew.bat bootRun --console=plain
```

기본 API 주소는 `http://localhost:8080`이다. 요청 경로와 마지막 `/`의 유무는 [API 명세](./docs/4-3-api-spec.md)를 따른다. 전체·부분 Postman 컬렉션 실행 방법은 [테스트 안내](./docs/postman/README.md)에 있다.

## AI 활용 범위

이번 AI(Codex) 지원 작업은 **기존 프로젝트의 설계·기본 구현을 바탕으로 문서 작성과 테스트를 수행하는 범위**에서 시작했다. 이후 테스트 실패에 대한 수정안을 제시했고, 개발자의 적용 요청에 따라 일부 기능 코드도 수정했다. 따라서 AI 지원 범위에는 문서·테스트뿐 아니라 아래의 보완 구현도 포함된다.

| 구분 | 작업 범위와 AI의 역할 |
|---|---|
| 기존 설계·기본 구현 | 회원·메뉴·주문 모델, JPA 관계, 계층 구조, JWT 인증, 역할·소유권 및 주문 상태 로직 등 기존 소스가 문서화와 테스트의 기준이었다. 이번 문서 작성 과정에서 이 구조를 새로 구현한 것은 아니다. |
| AI 도움 — 문서 작성 | 현재 코드 분석을 바탕으로 ERD, 테이블 명세, API 요청·응답 예시, Mermaid 인프라 다이어그램, README와 테스트 보고서를 작성·정리했다. 결제 설계안은 구현된 기능과 구분했다. |
| AI 도움 — 테스트 작성·실행 | Postman 컬렉션·검증 스크립트 작성, CLI 실행, 실제 PostgreSQL 확인, 실패 분석, 수정 부분 재검증과 결과 정리를 수행했다. |
| AI 도움 — 승인 후 보완 구현 | 숫자 필드 검증, 생성 응답 201, 메뉴 단건 공개 조회, 삭제 메뉴 조회·수정·재삭제 404, 주문 ID 응답 추가를 적용했다. 변경한 기능 소스는 8개 파일이다. |
| 개발자의 결정 | 코드 기준 문서화 방식, PostgreSQL·Docker 환경, Postman CLI 사용, 결제를 제외한 수정 및 재검증 범위를 결정하고 코드 적용을 요청했다. |

보완 구현의 파일별 내역은 [재검증 보고서의 적용한 수정](./docs/5-1-fix-retest-report.md#적용한-수정)에 기록했다. 문서·테스트 지원과 기존 설계·구현을 구분하되, AI가 실제로 수행한 코드 수정도 함께 공개한다.
