## 기능별 구현·검증 범위

아래 표는 두 차례의 PostgreSQL/Postman 실행에서 확인한 범위를 모은 것이다. 전체 기능의 모든 예외·동시성 조건을 검증했다는 의미는 아니다.

| 기능 | 현재 구현 | 실행으로 확인한 범위 |
|---|---|---|
| 회원가입 | 있음, 성공 201 | 수정 후 4명 생성 201. 중복·비밀번호 검증 및 BCrypt 저장은 최초 실행에서 확인 |
| 로그인 | 있음, JWT 발급 | 두 실행에서 JWT 발급 200. 잘못된 비밀번호 401은 최초 실행에서 확인 |
| 메뉴 등록 | 있음, OWNER 전용, 성공 201 | 수정 후 생성 201·비로그인 거절. CUSTOMER 거절·가격 0 검증은 최초 실행에서 확인 |
| 메뉴 목록 | 있음, 비로그인 공개 | 최초 실행에서 공개 조회 및 삭제 메뉴 제외 확인. 부분 재검증 대상은 아님 |
| 메뉴 단건 조회 | 있음, 비로그인 공개 | 수정 후 활성 메뉴 200, 없는 메뉴·삭제 메뉴 404 |
| 메뉴 수정 | 있음, 본인 OWNER | 수정 후 본인 수정 200, 다른 OWNER 403, 삭제 메뉴 404 |
| 메뉴 삭제 | Soft Delete | 수정 후 본인 204, 다른 OWNER 403, 재삭제 404. 행 유지·deleted_at은 최초 DB 조회에서 확인 |
| 주문 생성 | 있음, CUSTOMER 전용, 성공 201 | 수정 후 ID·금액·초기 상태, 필수값·수량 검증, OWNER·없는 메뉴·삭제 메뉴 거절 |
| 주문 목록 | 있음, 역할별 범위 | 수정 후 본인과 다른 계정의 조회 범위, 메뉴 삭제 후 주문 2건 보존 |
| 주문 취소 | 있음, 본인 ORDERED 주문 | 최초 Postman 실행은 선행 조건 미충족. 수정 후 부분 재검증에서 제외 |
| 주문 상태 변경 | 있음, PAID → ACCEPTED → COMPLETED | 최초 Postman 실행은 선행 조건 미충족. 수정 후 부분 재검증에서 제외 |
| 결제 | **미구현** | 호출 가능한 API와 payments 테이블 없음. 테스트 통과 항목에 포함하지 않음 |

## 실행 기록을 읽는 기준

| 기록 | 실행 시각 (Asia/Seoul) | 집계 기준과 결과 |
|---|---|---|
| 수정 전 전체 테스트 | 2026-10-08 16:42:20 | 과제 시나리오 39개: 통과 13 / 실패 14 / 선행 조건 미충족 8 / 미구현 4 |
| 수정 후 부분 재검증 | 2026-10-08 17:02:18 | 요청 40개, assertion 67개: 모두 통과, 실패·건너뜀 0 |

시나리오 수, 역할별로 나눈 요청 수, assertion 수는 서로 다른 집계다. 두 실행의 숫자를 더해 새로운 전체 통과율을 만들지 않는다. 이전 실패 14개는 해결을 확인했지만, 이전에 건너뛴 취소·상태 변경 등을 모두 검증한 것은 아니다.

이전 H2 테스트는 PostgreSQL/Postman 실행보다 앞선 별도 로컬 기록이다. 저장소에 공유하는 현재 검증 근거는 이 안내에서 연결한 두 차례의 PostgreSQL 실행 보고서와 결과 JSON이다.

## 명세와 증거의 구분

- **4-1~4-4:** 현재 소스와 확인된 실행 환경의 설명이다. API 예시의 ID·주소·토큰 자리 표시는 설명용이며 실응답을 복사한 것이 아니다.
- **5-1 보고서 및 결과 JSON:** 각 실행 당시의 결과다. 이전 실패 기록을 현재 통과 결과로 덮어쓰지 않는다.
- **테이블 명세:** 엔티티에 선언된 매핑을 기준으로 한다. 실제 DB에서는 일부 데이터와 컬럼 타입을 조회했으며, 전체 DDL을 대조한 것은 아니다.
- **결제 설계안:** ERD·테이블·API에 별도로 표시한 미구현 제안이다. 결제 기록 저장과 주문 PAID 전환은 아직 구현되지 않았다.
